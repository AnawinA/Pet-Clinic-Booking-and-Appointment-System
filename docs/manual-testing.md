# คู่มือทดสอบด้วยมนุษย์ (Manual UAT) — PetCare System

คู่มือนี้ใช้สำหรับให้คนลองใช้งานจริงบน stack ที่รันด้วย Docker Compose
ทุกขั้นตอนอ้างอิงชื่อปุ่ม/เมนูจริงใน UI และมีผลลัพธ์ที่คาดหวังให้ติ๊กผ่าน/ไม่ผ่าน

---

## 1. เตรียม environment

```bash
cp .env.example .env          # ครั้งแรกเท่านั้น
docker compose up -d --build
docker compose run --rm web1 python -m scripts.seed
```

ตรวจความพร้อมก่อนเริ่ม:

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost/api/v1/health/ready   # 200
curl -s -D - -o /dev/null http://localhost/api/v1/health/live | grep -i x-instance-id
```

| บริการ | URL |
|---|---|
| แอปพลิเคชัน | http://localhost |
| Grafana | http://localhost:3000 (`admin` / `admin` เว้นแต่ตั้งใน `.env`) |
| Prometheus | http://localhost:9090 |

### บัญชีทดสอบ (หลัง seed)

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| STAFF | `staff@petcare.local` | `Petcare123!` |
| VET | `vet1@petcare.local` | `Petcare123!` |
| VET | `vet2@petcare.local` | `Petcare123!` |
| OWNER | `owner1@petcare.local` | `Petcare123!` |
| OWNER | `owner2@petcare.local` | `Petcare123!` |

สัตว์เลี้ยง: owner1 มี `มะม่วง (Dog)` และ `ส้มจี๊ด (Cat)`; owner2 มี `โกโก้ (Dog)`

### เปิดหลายบทบาทพร้อมกัน

token ถูกเก็บใน `localStorage` ของเบราว์เซอร์เดียวกัน การล็อกอินบทบาทใหม่จะแทนที่บทบาทเดิม
ให้ใช้ **3 browser/profile แยกกัน** เช่น Chrome ปกติ (OWNER), Chrome โปรไฟล์ที่ 2 (STAFF), Firefox (VET)
หรือใช้ Chrome + Edge + โปรไฟล์ไม่ระบุตัวตนคนละหน้าต่าง

### หมายเหตุข้อมูลทดสอบ

- seed สร้างกะ 09:00–17:00 ของ vet1/vet2 ไว้ล่วงหน้า 7 วัน (วันนี้ถึง +6)
- สล็อตละ 30 นาที; เลือกวันพรุ่งนี้เพื่อให้เหลือเวลา > 2 ชั่วโมงสำหรับทดสอบยกเลิก
- การทดสอบจะสร้างนัด/บันทึกจริงในฐานข้อมูล dev ควรยกเลิกนัดที่ทดสอบเมื่อจบ
- อย่า `docker compose down -v` เว้นแต่ต้องการล้างข้อมูลทั้งหมดจริง ๆ

## 2. เคสทดสอบ

ทำตามลำดับได้เลย แต่ละข้อมีช่องผลลัพธ์ท้ายบท

### T0 — Smoke & session

1. เปิด `http://localhost` → ถูกพาไป `/login`
2. ล็อกอิน `owner1@petcare.local` → ถึงหน้า **นัดของฉัน**
3. กด refresh (F5) → ยังอยู่ในระบบ ไม่ต้องล็อกอินซ้ำ
4. กด **ออกจากระบบ** → กลับหน้า login; กด Back ของเบราว์เซอร์ → ไม่กลับเข้าไป

**คาดหวัง:** ข้อ 2–4 ทำงานตามลำดับ; ลองล็อกอินด้วยรหัสผิดต้องเห็นข้อความ error ชัดเจนและไม่เข้าสู่ระบบ

### T1 — สมัครสมาชิก + เพิ่มสัตว์เลี้ยง (OWNER)

1. ที่หน้า login กด **สมัครสมาชิกสำหรับเจ้าของสัตว์เลี้ยง**
2. กรอกชื่อ/อีเมลใหม่ (เช่น `uat-owner-<เวลา>@petcare.local`)/รหัสผ่าน 8 ตัวอักษรขึ้นไป/ยืนยันรหัส
3. กด **สมัครสมาชิก** → เข้าสู่ระบบอัตโนมัติและอยู่หน้า **นัดของฉัน**
4. ไปเมนู **สัตว์เลี้ยง** → กรอกชื่อ `ทดสอบ-<เวลา>`, ชนิด `Cat`, น้ำหนัก `3.5` → **เพิ่มสัตว์เลี้ยง**
5. กด **แก้ไข** การ์ดสัตว์เลี้ยง → เปลี่ยนน้ำหนักเป็น `4.0` → **บันทึกการแก้ไข**

**คาดหวัง:** toast สำเร็จทุกครั้ง, การ์ดสัตว์เลี้ยงแสดงข้อมูลใหม่, รหัสผ่านยืนยันไม่ตรงกันถูกปฏิเสธ

### T2 — จองนัด (OWNER)

1. เมนู **จองนัด** → วันที่ = พรุ่งนี้ → สัตวแพทย์ = `นพ.วีรภัทร สุขใจ`
2. เลือกช่วงเวลาว่างช่วงใดก็ได้ที่แสดง (เช่น ช่วง 11:00–15:00) จดเวลาไว้ → เลือกสัตว์เลี้ยง `มะม่วง (Dog)` → อาการ `ซึม ไม่กินอาหาร` → **ยืนยันการจอง**
3. ระบบพาไป **นัดของฉัน** → การ์ดใหม่สถานะ **จองแล้ว** เวลา/แพทย์ตรงกับที่เลือก
4. กลับไป **จองนัด** วันที่/แพทย์เดิม → ช่วงเวลาที่เพิ่งจองต้องหายไปจากรายการ

**คาดหวัง:** จองสำเร็จครั้งเดียว, availability อัปเดตภายใน 5 วินาที, ไม่มีปุ่มให้จองซ้ำสล็อตเดิม

### T3 — Double booking (OWNER 2 คน)

1. เปิด OWNER สองเบราว์เซอร์: owner1 และ owner2 ที่หน้า **จองนัด** วัน/แพทย์เดียวกัน
2. เลือกช่วงเวลาว่างเดียวกันทั้งสองฝั่ง (ยังไม่กดยืนยัน)
3. กด **ยืนยันการจอง** พร้อมกัน (หรือสลับกันเร็ว ๆ)

**คาดหวัง:** สำเร็จเพียงคนเดียว; อีกคนได้ toast แจ้งข้อผิดพลาดว่าช่วงเวลาถูกจอง (HTTP 409)
และรายการช่วงเวลาฝั่งที่พลาดจะรีเฟรชจนสล็อตนั้นหายไป

### T4 — เลื่อนนัดโดย STAFF

1. เบราว์เซอร์ STAFF → เมนู **กระดานนัด** → วันที่เดียวกับ T2 → สัตวแพทย์คนเดิม
2. หาการ์ดของ `มะม่วง` (ดูจากอาการที่กรอก) → กด **เลื่อนนัด**
3. ใส่ **วันและเวลาใหม่ (เวลาไทย)** เป็นเวลาที่ว่างจริงของวันเดิม (เช็กจากหน้า **จองนัด** ของ OWNER หรือเลือกเวลาที่ไม่มีนัดอื่นในกระดาน) → **ยืนยันเลื่อนนัด**
4. ตรวจ toast และเวลาบนการ์ดเปลี่ยนเป็นเวลาที่เลือก
5. เบราว์เซอร์ OWNER เปิด **นัดของฉัน** ค้างไว้ → ภายใน ~5 วินาที เวลาต้องเปลี่ยนตามโดยไม่ต้อง refresh
6. ทดสอบกรณีชน: กด **เลื่อนนัด** อีกครั้ง → ใส่เวลาที่มีนัดอื่นอยู่แล้ว → **ยืนยันเลื่อนนัด**

**คาดหวัง:** ข้อ 3–5 สำเร็จ; ข้อ 6 แสดง error 409 และเวลาเดิมยังอยู่ (ไม่ถูกเปลี่ยนครึ่งทาง)

### T5 — ยกเลิกนัด (OWNER)

1. OWNER → **นัดของฉัน** → การ์ดนัดจาก T4 → **ยกเลิกนัด**
2. กรอกเหตุผล `UAT ทดสอบยกเลิก` → **ยืนยันยกเลิก**
3. การ์ดแสดงสถานะ **ยกเลิก**, เหตุผลที่ยกเลิก, และไม่มีปุ่มยกเลิกนัดแล้ว
4. กลับไป **จองนัด** วัน/แพทย์/เวลาเดิม → ช่วงเวลาต้องกลับมาว่างอีกครั้ง
5. (ถ้ามีสล็อตวันนี้ที่เหลือน้อยกว่า 2 ชั่วโมง) ลองจองสล็อตนั้น → ปุ่ม **ยกเลิกนัด** ต้องไม่แสดง
   และมีข้อความแจ้งให้ติดต่อคลินิก

**คาดหวัง:** ยกเลิกสำเร็จ คืนสล็อตทันที และกฎหน้าต่างยกเลิกทำงานตามเวลา

### T6 — เส้นทางคลินิก: เช็คอิน → รักษา → เสร็จสิ้น

1. OWNER จองนัดใหม่ล่วงหน้าตาม T2 (จำวัน/เวลา)
2. STAFF → **กระดานนัด** → วันที่นั้น → การ์ดนัด → กด **เช็คอิน**
3. การ์ดสถานะเปลี่ยนเป็น **เช็คอิน** และปุ่มเปลี่ยนเป็น **เริ่มรักษา** → กด **เริ่มรักษา**
4. VET (`vet1`) → **ตารางงาน** → วันที่นั้น → การ์ดนัด → **เปิดเคส**
5. กรอกบันทึก `ตรวจแล้ว อาการปกติ` → **บันทึกเวอร์ชันใหม่** → ทำซ้ำอีกครั้งด้วยข้อความที่สอง
6. ตรวจว่าแสดง **เวอร์ชัน 1** และ **เวอร์ชัน 2** เรียงถูกต้อง
7. OWNER → **นัดของฉัน** → **รายละเอียด** → เห็นสถานะ **กำลังรักษา** และบันทึกการรักษา
8. STAFF → **กระดานนัด** → กด **เสร็จสิ้น**
9. VET → **เปิดเคส** อีกครั้ง → ตรวจ **ประวัติการรักษาของสัตว์ตัวนี้**

**คาดหวัง:** สถานะไหลตามลำดับ BOOKED → CHECKED_IN → IN_TREATMENT → COMPLETED,
บันทึกมีเวอร์ชันเพิ่มขึ้น, owner เห็นบันทึก, ประวัติสัตว์เลี้ยงแสดงรายการพร้อมจำนวนบันทึก

### T7 — คำขอปรับเวลา (VET → STAFF อนุมัติ/ปฏิเสธ)

1. OWNER จองนัดใหม่ (สถานะ **จองแล้ว**) กับ `vet1`
2. VET → **ตารางงาน** → **เปิดเคส** ของนัดนั้น → ส่วน **ขอปรับเวลา**
3. ใส่ **เวลาใหม่ (เวลาไทย)** ที่ว่าง + เหตุผล → **ส่งคำขอถึงเจ้าหน้าที่**
4. STAFF → **คำขอปรับเวลา** → เห็นคำขอ → กรอกบันทึกผล (ไม่บังคับ) → **อนุมัติ**
5. ตรวจ **กระดานนัด** และฝั่ง OWNER ว่าเวลาถูกเลื่อนจริง
6. ทำซ้ำข้อ 2–3 แล้วให้ STAFF กด **ปฏิเสธ** → เวลาต้องไม่เปลี่ยน และคำขอหายจากรายการ PENDING

**คาดหวัง:** อนุมัติแล้วเลื่อนนัดทันที; ถ้าสล็อตชนตอนอนุมัติต้องแสดง error และคำขอยังคง PENDING;
ปฏิเสธแล้วนัดคงเดิม

### T8 — คิวสดและเวลาคาดการณ์ (OWNER)

1. OWNER → **คิวสด** → เลือกวันที่ที่มีนัดหลายรายการ + สัตวแพทย์
2. ตรวจลำดับคิว, ช่วงเวลา, จำนวน **คิวก่อนหน้า**, เวลาคาดว่าจะเริ่ม
3. ให้ STAFF เช็คอินนัดลำดับแรก → กลับมาดูหน้าคิว OWNER ภายใน ~3 วินาที

**คาดหวัง:** คิวเรียงตามเวลา, ตัวเลขคิวก่อนหน้าถูกต้อง, หน้าอัปเดตอัตโนมัติโดยไม่ต้อง refresh

### T9 — จัดการกะ (STAFF)

1. STAFF → **จัดการกะ** → เลือกวันที่ `+7 วัน` (ถ้าเลือกวันใน 7 วันแรกจะมีกะเดิมอยู่)
2. เลือกสัตวแพทย์ → เวลา `09:00`–`12:00` → **สร้างกะ**
3. ตรวจว่าการ์ดกะปรากฏ และหน้า **จองนัด** ของวันนั้นมีสล็อต 09:00–11:30
4. สร้างกะซ้อน เช่น `10:00`–`11:00` ของแพทย์คนเดิม → ต้องถูกปฏิเสธ
5. กด **ลบ** กะที่สร้าง → toast และสล็อตของวันนั้นหายจากหน้า **จองนัด**

**คาดหวัง:** สร้าง/ลบกะได้, กะซ้อนถูกปฏิเสธ, availability สอดคล้องกับกะ

### T10 — สร้างบัญชีทีมงาน (STAFF)

1. STAFF → **สร้างบัญชี** → กรอกชื่อ, อีเมลใหม่, เบอร์โทร, บทบาท `VET`, รหัสผ่านชั่วคราว 8 ตัวขึ้นไป
2. กด **สร้างบัญชี** → toast สำเร็จ
3. ออกจากระบบ → ล็อกอินบัญชีใหม่ → ต้องไปหน้า **ตารางงาน** (`/vet/schedule`)
4. ทำซ้ำโดยเลือกบทบาท `STAFF` → ล็อกอินแล้วต้องไปหน้า **กระดานนัด**

**คาดหวัง:** บัญชีใหม่ล็อกอินได้และถูกพาไปหน้าตามบทบาท; OWNER ไม่เห็นเมนูนี้

### T11 — Audit Log (STAFF)

1. เปิดรายละเอียดนัดของ OWNER เพื่อคัดลอก UUID จาก URL `/owner/appointments/<uuid>`
2. STAFF → **Audit Log** → วาง UUID ในช่อง **Entity ID** → ดูรายการ
3. เปิด **ดูรายละเอียด before/after** ของรายการ CREATE / STATUS_CHANGE / RESCHEDULE / CANCEL

**คาดหวัง:** มีรายการครบตามที่ทำใน T2–T7, แสดง `actor_role`, เวลา, และค่า before/after;
ไม่มีปุ่มแก้ไข/ลบ log (append-only)

### T12 — การแจ้งเตือน (OWNER/VET)

1. OWNER → **แจ้งเตือน** → ต้องมีรายการจากการจอง/เลื่อน/ยกเลิก
2. กด **อ่านแล้ว** รายการหนึ่ง → badge ตัวเลขบนเมนูลดลง และรายการจางลง
3. VET → **แจ้งเตือน** → ต้องมีแจ้งเตือนนัดใหม่/การเปลี่ยนแปลงของตัวเอง

**คาดหวัง:** ผู้รับถูกต้องตามบทบาท, mark read ทำงาน, ตัวเลข unread ตรงกับรายการใหม่

### T13 — สิทธิ์การเข้าถึง (RBAC)

1. OWNER พิมพ์ `/staff/board` ใน address bar → ต้องถูกพากลับ `/owner/appointments`
2. VET พิมพ์ `/owner/book` → ต้องถูกพากลับ `/vet/schedule`
3. ออกจากระบบ แล้วเปิด `/owner/appointments` → ไป `/login` และล็อกอินสำเร็จแล้วกลับมาหน้านั้น
4. (สำหรับนักพัฒนา) ยิง API ด้วย token OWNER ไป endpoint ของ STAFF เช่น
   `GET /api/v1/reschedule-requests` → ต้องได้ **403** พร้อม envelope
   `{"error":{"code":"...","message":"...","details":{...}}}`

**คาดหวัง:** UI guard ทำงานทุกข้อ, API ปฏิเสธสิทธิ์ด้วย 403 ไม่ใช่ 500

### T14 — Monitoring & High Availability

1. ยิง health 10 ครั้งแล้วดู header:
   ```bash
   for i in $(seq 1 10); do
     curl -s -D - -o /dev/null http://localhost/api/v1/health/live \
       | tr -d '\r' | awk -F': ' 'tolower($1)=="x-instance-id"{print $2}'
   done
   ```
2. เปิด Prometheus `http://localhost:9090/targets` → ทุก target ต้อง `UP`
3. เปิด Grafana → dashboard **PetCare Overview** → มีข้อมูล request rate/latency
4. ตรวจว่า `http://localhost/metrics` ถูกปิด (404) แต่ Prometheus scrape ภายในได้

**คาดหวัง:** header สลับ `web1`/`web2` อย่างสมดุล, target ครบ, dashboard แสดงข้อมูล,
ไม่เปิดเผย metrics ผ่าน nginx

### T15 — Resilience (ไม่บังคับ, สำหรับคนดูแลระบบ)

1. ทำตาม `docs/runbook.md` หัวข้อ 4.2: หยุด worker → จอง 3–5 นัด → เริ่ม worker
   → ตรวจว่า notification มาครบและไม่ซ้ำ
2. ทำตามหัวข้อ 4.1: `docker exec petcare-web1-1 kill -9 1` → ระหว่างนั้นใช้งานเว็บต่อ
   ต้องไม่เห็น 5xx และ web1 กลับมาเองภายใน ~10 วินาที

**คาดหวัง:** ระบบกู้คืนได้เองโดยผู้ใช้ไม่สะดุด; ตรวจผลใน `docker compose ps` และ notification

## 4. ถ้าพบปัญหา ให้เก็บหลักฐานเหล่านี้

- เวลาที่เกิด (โดยประมาณ) และบทบาท/บัญชีที่ใช้
- URL และลำดับขั้นตอนก่อนเกิดปัญหา
- ภาพหน้าจอหรือวิดีโอ
- ข้อความ error บนจอ (toast/ErrorText) และถ้าเป็นนักพัฒนา: response status + body
- ถ้ามี: `X-Request-ID` จาก response header และ Audit Log ที่เกี่ยวข้อง
- ตรวจ log ฝั่งเซิร์ฟเวอร์: `docker compose logs --tail=100 web1 web2 worker nginx`

## 5. ข้อจำกัดที่รู้ (ไม่ถือเป็นบั๊ก)

- หน้าต่าง ๆ ใช้ polling ทุก 3–5 วินาที ไม่ใช่ WebSocket จึงอาจหน่วงไม่เกิน 5 วินาที
- การแจ้งเตือนเป็น in-app เท่านั้น ยังไม่ส่งอีเมล/SMS
- OWNER ยังไม่มีปุ่มขอเลื่อนนัดเองใน UI; การเลื่อนทำได้โดย STAFF ที่กระดานนัด
  หรือ VET ส่งคำขอปรับเวลาให้ STAFF อนุมัติ
- การยกเลิกโดย OWNER ทำได้เมื่อเหลือเวลาอย่างน้อย 2 ชั่วโมงก่อนนัด
- ข้อมูล demo ทั้งหมดใช้รหัสผ่านเดียวกันและห้ามใช้ใน production
